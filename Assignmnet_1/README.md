# Machine Learning Assignment — Customer Churn Benchmark

## Project Overview

This repository contains the complete machine-learning workflow, from raw Kaggle data and exploratory analysis to data cleaning, model training, benchmarking, evaluation, and saved models ready for inference.

The project is organized so that raw data, processed data, model training notebooks, trained models, benchmark outputs, experiments, and observations are kept separately.

## 1. `raw_data/`

The `raw_data` folder contains the original customer-churn datasets downloaded from Kaggle.

These files are the raw inputs before the cleaning and preprocessing performed during analysis. The raw data is kept separate so that the original source data is preserved.

---

## 2. `processed_data/`

The `processed_data` folder contains the cleaned/processed data generated during the analysis notebook.

The main file is:

```text
processed_customer_churn.csv.zip
```
First extract the zip file to get the bellow following file
```text
processed_customer_churn.csv
```
this file has been used all across the noteooks


The analysis workflow removes or handles:

- Missing values
- Duplicate records
- Unknown/unwanted values

The resulting processed data is then used for the model-training workflow.

---

## 3. `notebooks/`

The `notebooks` folder contains the Jupyter notebooks used during the project.

There is a separate training notebook for each model. This makes it possible to train, inspect, and tune a particular model independently.

The model training notebooks cover:

- Logistic Regression
- KNN
- Decision Tree
- Random Forest
- Gradient Boosting
- SVM

If a specific model needs tuning, its corresponding notebook can be opened and its configuration can be changed before retraining and saving the updated model.

The folder also contains the analysis/EDA notebook used for understanding and cleaning the dataset.

---

## 4. Analysis / EDA Notebook

The analysis notebook is used before model training to understand and prepare the data.

The analysis includes:

- Exploratory Data Analysis (EDA)
- Basic data cleaning
- Missing-value handling
- Duplicate removal
- Handling unknown values
- Examination of feature relationships
- Statistical testing

T-tests and chi-square tests were also used to investigate relationships between features and the data/target.

The cleaned result generated by this analysis is stored in `processed_data/`.

---

## 5. `models/`

The `models` folder contains trained model pipelines saved as `.joblib` files.

These models are already trained and can be loaded for inference without retraining.

The folder contains:

```text
Decision_tree_model_pipeline.joblib
Gradient_boosting_model_pipeline.joblib
KNN_model_pipeline.joblib
Logistic_regression_model_pipeline.joblib
Random_Forest_model_pipeline.joblib
SVM_model_pipeline.joblib
```

If a model configuration is changed, the corresponding notebook can be rerun and the updated trained pipeline can be saved again.

## 6. `benchmark_outputs/`

The `benchmark_outputs` folder contains the outputs produced by the model experiments.

### Benchmark results

```text
model_benchmark_results.csv
```

This CSV contains the numerical results recorded during the model benchmarking experiments.

### Confusion matrices

Confusion-matrix images are provided for the trained models, including:

- Decision Tree
- Gradient Boosting
- KNN
- Logistic Regression
- Random Forest
- SVM

These provide a visual view of the prediction results for each model.

### Additional visualizations

The folder also contains:

```text
experiment_confusion_matrices.png
Shallow_vs_DeepTree.png
```

These provide additional comparisons of model behavior and configurations.

---

## 7. `experiments.ipynb`

`experiments.ipynb` contains the experiments performed across the models.

It is used to run the benchmark workflow, compare model configurations, and collect the resulting performance and timing information.

This notebook can be rerun when model configurations are changed or when the benchmark needs to be reproduced.

---

## 8. `experiments.py`

`experiments.py` contains the script-based version of the experiment workflow.

It can be used to run the experiments without relying only on the Jupyter Notebook interface.

For example:

```bash
python experiments.py
```

The resulting benchmark outputs are stored in `benchmark_outputs/`.

---

## 9. `observations_updated.md`

`observations_updated.md` contains the reasoning and interpretation of the experiments.

It documents:

- Why the models were selected
- What was observed during the experiments
- Training, validation, and test performance
- Effects of changing model configurations
- Training and inference time
- Bias/variance observations
- Final model-selection reasoning
- Overall conclusions

It also answers the required questions:

1. Which model performed best on training data?
2. Which model performed best on validation data?
3. Which model generalized best to the final test set?
4. Which algorithm was most interpretable?
5. Which algorithm was fastest at inference time?
6. Which model would be chosen if explainability were a requirement?
7. Which model would be chosen if predictive performance were the primary objective?
8. Did any model show signs of high bias or high variance?

The benchmark CSV provides the numerical evidence, while this file explains the reasoning behind those results.

# Setup and Execution

## Prerequisites

The project requires Python and Jupyter Notebook/JupyterLab.

It is recommended to create a virtual environment:

### Windows

```bash
python -m venv .venv
.venv\Scripts\activate
```

### macOS / Linux

```bash
python3 -m venv .venv
source .venv/bin/activate
```

If the project contains a `requirements.txt` file, install dependencies with:

```bash
pip install -r requirements.txt
```

Then start Jupyter:

```bash
jupyter notebook
```

or:

```bash
jupyter lab
```

If no requirements file is provided, install the Python packages required by the notebooks before running them.

---

## Recommended Execution Order

### Step 1 — Raw data

Start with the original datasets in:

```text
raw_data/
```

Do not modify the raw files directly.

### Step 2 — Analysis and cleaning

Open the analysis notebook inside:

```text
notebooks/
```

Run the EDA, cleaning, and statistical-analysis workflow.

This produces the cleaned/processed dataset in:

```text
processed_data/
```

### Step 3 — Train individual models

Open the appropriate model notebook in `notebooks/`.

Each model has its own notebook. Run the notebook to train the model and save its trained pipeline into:

```text
models/
```

If further tuning is required, change the configuration in that model's notebook and retrain it.

### Step 4 — Run the benchmark

Run:

```text
experiments.ipynb
```

or:

```bash
python experiments.py
```

This performs the model experiments and produces the benchmark results.

### Step 5 — Review outputs

The benchmark results and visualizations are available in:

```text
benchmark_outputs/
```

The main numerical result is:

```text
model_benchmark_results.csv
```

The PNG files contain confusion matrices and other model comparisons.

### Step 6 — Review conclusions

Finally, read:

```text
observations_updated.md
```

This contains the interpretation of the experimental results and the required assignment observations.

---

## Tuning a Specific Model

The project structure allows individual models to be changed without changing the whole workflow.

For example, to tune the Random Forest:

1. Open its training notebook in `notebooks/`.
2. Change the required model configuration.
3. Run the notebook.
4. Save the updated trained pipeline in `models/`.
5. Run the relevant benchmark experiment again.
6. Compare the new results with the previous results.
7. Update `observations_updated.md` if the conclusions change.

The same process can be followed for Logistic Regression, KNN, Decision Tree, Gradient Boosting, or SVM.
