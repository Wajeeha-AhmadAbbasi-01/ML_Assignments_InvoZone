# Assignment 2 — Customer Segmentation with K-Means, DBSCAN, and PCA

This project implements an unsupervised customer-segmentation workflow using **K-Means clustering**, **DBSCAN**, and **Principal Component Analysis (PCA)**.

The project is organized so that the raw dataset, main analysis notebook, generated results, visualizations, and observations are kept in separate folders/files. The main notebook contains the complete preprocessing, scaling, clustering, evaluation, and PCA experiments.

---

## Project Overview

The objective of this assignment is to explore customer behavior using unsupervised learning techniques and understand how different clustering methods group the data.

The project includes:

- Data loading and initial inspection
- Data cleaning and preprocessing
- Selection of meaningful numerical behavioral features
- Handling of missing/invalid values
- Removal of identifiers that should not influence distance calculations
- Feature scaling
- K-Means clustering experiments
- Elbow-method analysis using inertia
- Silhouette-score evaluation
- K-Means cluster profiling and descriptive statistics
- DBSCAN experiments with multiple parameter configurations
- Identification of DBSCAN noise points
- PCA dimensionality reduction
- Visualization of clusters in PCA space
- Comparison of K-Means and DBSCAN results
- Written observations and interpretation of the experiments

> **Important:** The clusters discovered in this project are exploratory groups based on the selected behavioral features. They should not automatically be interpreted as definitive real-world business segments.

# Methodology

## 1. Data Loading and Inspection

The raw customer dataset is stored in:

```text
data/Customer_DataSet.csv
```

The notebook loads the dataset and performs an initial inspection to understand:

- Dataset dimensions
- Column names
- Data types
- Missing values
- Invalid values
- Feature distributions
- Potential identifier columns
- Numerical variables suitable for clustering

The purpose of this stage is to understand the structure and quality of the data before applying clustering algorithms.

---

## 2. Data Preprocessing

Before clustering, the data is prepared for distance-based machine-learning algorithms.

The preprocessing workflow includes:

- Checking for missing values
- Handling invalid values
- Selecting meaningful numerical behavioral features
- Removing identifiers or other columns that should not influence distance calculations
- Preparing the final feature matrix

The selected variables should represent customer behavior rather than arbitrary identifiers.

---

## 3. Feature Scaling

Feature scaling is performed before clustering.

This is particularly important because both **K-Means** and **DBSCAN** depend on distances between observations.

If one feature has a much larger numerical range than another, it can dominate the distance calculation. Scaling puts the selected features on comparable scales so that clustering is not controlled by a single high-magnitude feature.

The notebook performs the required scaling as part of the preprocessing pipeline.

# K-Means Experiments

K-Means is used to divide the customers into a predefined number of clusters.

The notebook experiments with several values of `K` rather than selecting the number of clusters arbitrarily.

## Elbow Method

The notebook calculates K-Means **inertia** for multiple values of `K`.

The resulting values are visualized in:

```text
outputs/kmeans_elbow.png
```

The elbow plot helps identify a point where increasing the number of clusters produces diminishing improvements in within-cluster compactness.

---

## Silhouette Analysis

Silhouette scores are calculated for useful K-Means configurations.

The results are visualized in:

```text
outputs/kmeans_silhouette.png
```

The silhouette score provides an additional measure of how well-separated and internally cohesive the clusters are.

The final value of `K` is selected using the combination of:

- Elbow-method behavior
- Silhouette-score results
- Interpretability of the resulting clusters
- Overall clustering behavior

# DBSCAN Experiments

DBSCAN is used as a second clustering approach.

Unlike K-Means, DBSCAN does not require the number of clusters to be specified in advance. Instead, it identifies dense regions using parameters such as:

- `eps`
- `min_samples`

The notebook evaluates multiple combinations of these parameters.

The parameter-search results are saved in:

```text
outputs/dbscan_grid_search.csv
```

---

## DBSCAN Noise Detection

One of the important properties of DBSCAN is its ability to classify observations as **noise/outliers**.

Noise points are represented separately from the discovered clusters.

This allows the project to compare DBSCAN's treatment of unusual observations with the behavior of K-Means, where every observation is assigned to a cluster.

---

# PCA Analysis

Principal Component Analysis (PCA) is used to reduce the dimensionality of the scaled feature space for visualization and analysis.

PCA transforms the original feature space into a smaller number of principal components while retaining as much variance as possible.

The explained-variance visualization is stored in:

This helps assess how much information is represented by the principal components.

# Interpretation Guidelines

The clustering results should be interpreted carefully.

## K-Means

K-Means assumes that clusters can be represented reasonably well by their centroids and tends to produce relatively compact groups.

Therefore, its results depend on:

- The selected number of clusters
- Feature scaling
- Feature selection
- Initial centroid placement
- The underlying geometry of the data

## DBSCAN

DBSCAN is density-based and can discover clusters without specifying the number of clusters beforehand.

Its results can be strongly affected by:

- `eps`
- `min_samples`
- Feature scaling
- Data density
- The presence of varying-density regions

DBSCAN also has the advantage of explicitly identifying observations that do not belong to a sufficiently dense region as noise.

## PCA

PCA is primarily used here to simplify visualization of a potentially high-dimensional feature space.

A two-dimensional PCA visualization does not necessarily show every relationship present in the original feature space. Therefore, PCA plots should be considered together with the numerical evaluation and cluster statistics.
